# 家族カードの買い物

家族カードで払った買い物のうち、**共有の買い物**をその場で記録しておく機能です。
カード明細を取り込むときに、この記録と家族カードの行を照らし合わせ、記録のない行を**妻の個人利用**として分けます。

- 記録: 「その他」→「家族カードの買い物」
- 照らし合わせ: 「その他」→「明細読み込み（CSVなど）」で家族カードのCSVを選ぶ

---

## 1. 全体の流れ

| 段階 | 内容 | 状態 |
|---|---|---|
| 1 | 共有の買い物を、使ったその場で記録する | 実装済み |
| 2 | 妻のスマホでログインできるようにする（Firebaseのルールに妻のUIDを追加） | Firebaseコンソールで設定 |
| 3 | 明細の取込で、家族カードの行と記録を照らし合わせる。記録のない行を妻の個人利用として分ける | 実装済み |

## 2. 記録のしかた

- **金額を入れて記録する。** 使った日・金額・店名・カテゴリー・メモを入れて「記録する」。必須は使った日と金額だけです。
- **レシートを撮って記録する。** 「レシートを撮って記録」から、レシート読み取りを開きます。
  レシート読み取りを「その他」から開いた場合も、確認画面の「記録先」を「家族カードの買い物」にすれば同じです。
- 一覧の行を押すと、その記録を直せます。×で削除します。

**記録は、家計簿の合計にはまだ入りません。** カード払いは明細の取込で家計簿に入るため、ここで入れると二重になるからです。

## 3. データの形

保存先は Firestore の `budgetData/familyCardPurchases` です。既存のルール（`budgetData/{document}`）の範囲なので、ルールの変更は要りません。

```
{
  items: {
    "<記録ID>": {
      id: "<記録ID>",
      date: "2026-11-08",      // 使った日（YYYY-MM-DD）
      store: "イオン",          // 店名（空のこともある）
      amount: 3280,            // 金額（円・整数）
      category: "食費",         // カテゴリー名（未定なら空）
      memo: "",
      source: "receipt",       // "receipt"（レシート）か "manual"（手入力）
      createdAt: "2026-11-08T03:12:45.000Z"
    }
  }
}
```

- **1件ずつ `merge` で書きます。** 夫婦が別々の端末から同時に記録しても、互いの記録を消しません。
  全件をまとめて上書きする形にすると、片方の記録が消えることがあります。
- **空の項目も必ず持たせます。** `merge` は書いた項目だけを上書きするため、項目を省くと、直す前の値が残ってしまいます。
- 削除は `deleteField()` で、その記録だけを消します。

## 4. 明細の取込と照らし合わせ

### 読める明細

次の2つの形式を読めます。**毎月は、本会員（夫）のアカウントの明細CSVを1つ取り込めば足ります。** 夫の利用と家族カードの利用が両方入っているためです。

#### A. 本会員のアカウントの明細CSV（おすすめ）

カード会社のサイトから本会員のアカウントでダウンロードする明細です（Shift_JIS。ファイル名は `202611.csv` のような支払月）。会員ごとに区切り行があり、その下に明細が並びます。

```
氏名　様,カード番号（一部伏せ字）,カード名      ← 区切り行（本会員）
利用日,利用店名,利用金額,支払区分,支払回数,今回の支払金額,備考
…
,,,,,小計
氏名　様,カード番号,カード名                  ← 区切り行（家族会員）
…
,,,,,小計
,,,,,総合計,
```

- **最初の区切り行の氏名を本会員とし、氏名の違う区切り行の下を家族カードとして扱います。** 本会員のスマホ決済用カード（iD など）は、氏名が同じなので本会員のままです。
- 金額は「今回の支払金額」を使います（分割払いは今月の分）。
- 取込先の月は、ファイル名の年月（`202611` → 2026年11月）から決めます。ファイル名に年月がなければ、最も多い利用月の翌月にします。

#### B. 家族会員のアカウントの明細CSV

家族会員のアカウントからダウンロードする明細です（見出し行なし）。列は次の並びです。

| 列 | 内容 | 例 |
|---|---|---|
| 1 | 利用日 | `2026/10/10` |
| 2 | 利用店名 | 全角英数は半角に直します（`ＲＯＣＫＥＴＮＯＷ  ＪＰＮ` → `ROCKETNOW JPN`） |
| 3 | 利用者 | `ご家族` の行を家族カードとして扱います |
| 4 | 支払区分 | `1回払い` |
| 6 | 支払月 | `26/11` → 2026年11月に取り込みます |
| 7 | 利用金額 | 海外利用はこちらを使います |
| 8 | 支払金額 | 空でなければこちらを使います |

利用日で始まらない行（氏名・合計など）は読み飛ばします。
見出し行のあるCSVでも、「利用者」の列があれば、`家族` を含む行を家族カードとして扱います。

### 取込済みの明細（同じ明細を別のファイルで読んだとき）

本会員のCSVと家族会員のCSV、またはPDFとCSVのように、同じ明細が別のファイルに入っていることがあります。二重に入らないよう、取込先の月にすでに入っている明細を見つけます。

- **利用日と金額が同じ明細を、取込済みとみなします。** PDFとCSVでは店名の書き方が違うため、店名は比べません。同じ日に同じ金額の利用が2回あれば、取込済みの数だけ対応させます。
- 取込済みの行は「取込済み」と出して、取り込みません。別の買い物だった場合は「別に取り込む」で取り込めます。
- 家族カードの行は、前回の振り分け（共有とそのカテゴリー、または妻個人）を引き継ぎます。家族カードとして取り込んだ共有の明細には `familyCard: true` の印が付いています。
- **PDFなどで家族カードの分を区別せずに共有へ入れていた場合、** 妻個人の行は「取込済みから移す」になります。取り込むと、共有のカテゴリーからその明細を外し、妻の個人利用に入れ直します。

### 照らし合わせのルール

- **金額が同じで、明細の利用日が記録日の前日から7日後まで**なら一致とみなします。通販は発送日に請求されて数日後になることがあるためです。
- 候補が複数あるときは、**日付のずれが小さい組**から決めます。1つの記録は1行にだけ使います。
- 一致した行は**共有**になり、記録のカテゴリーで取り込みます（カテゴリーが未定の記録なら、取込画面で選びます）。
- 一致しなかった行は**妻の個人利用**になります。

### 取込画面での手直し

- 行の「共有にする」「妻個人にする」で切り替えます。チェックを入れてカテゴリーを選んだ行も、共有になります。
- 照らし合わせできなかった記録は一覧で出ます。来月の明細に載る買い物は残しておけば、次の取込で照らし合わせます。金額が違って一致しなかった記録（分割発送など）は、行を共有に切り替えてから、記録を削除します。
- 取り込むと、共有として取り込んだ行と一致した記録は消えます。

## 5. 妻の個人利用

- 取り込んだ月の `wifePersonal`（`budgetMonths/{YYYY-MM}` の中）に、店名・金額・利用日を持ちます。
- **家計の合計・予算・グラフには入れません。** 家計簿の画面では、カテゴリーの下に「妻の個人利用」として別に出します。
- **精算は、夫払いと妻払いの差の半分に、妻の個人利用の全額を足します。** 家族カードの引き落としは夫の口座なので、妻の個人利用は全額を妻が夫に返す計算です。

```
妻→夫の精算額 = (夫払い − 妻払い) ÷ 2 + 妻の個人利用
（負になれば、夫→妻の精算）
```

- 精算レシート・テキスト出力・PayPayの請求文に、妻の個人利用の金額を出します。
- 誤って個人利用にした行は、一覧の×で消してから、カテゴリーに追加し直します。

## 6. 実装メモ

- 記録の画面と処理、照らし合わせ: `js/family-card.js`（`FamilyCardManager`・`matchFamilyRows`）
- 明細の読み取りと取込画面: `js/statement-import.js`（`parseSectionedCardRows`・`parseHeaderlessCardRows`・`findAlreadyImported`・`_applyFamilyMatching`・`_rowPlan`・`_renderFamilyPanel`）
- 妻の個人利用と精算: `js/budget.js`（`wifePersonalItems`・`addWifePersonal`・`calculateSettlement`）
- レシート読み取りとの接続: `js/receipt.js` の `target`（`'budget'` か `'family'`）
- テスト: `tests/family-card.test.mjs`。実際の明細は入れず、同じ列の並びの架空データで確かめています
